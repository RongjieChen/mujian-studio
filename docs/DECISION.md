# 选题决策与证据边界

2026-09-21。当前为实现阶段，功能完成度与测量结果以 README 和 evidence 为准。

## 决策

保留“推理游戏创作工坊”，产品名“幕间”。它采用互动影游的表现方式，首个垂直模板是短篇悬疑案件。单台 DGX Spark 承担创作阶段的模型推理；播放器使用已生成素材，不把视频生成的等待转嫁给玩家。

评分的 50% 是实用创新与技术深度，另 35% 是完整性和平台适配。只有文字生成影片不足以覆盖这些要求。需要交付可编辑、可验证、可导出的游戏，证明 Agent 能识别并修复修改引入的问题。本地性应由请求日志、内存、耗时、失败恢复和成本计算支撑，不能仅写“稳定、快速、低成本”。

## 从第一性原理比较

| 方向 | 有利条件 | 主要风险 | 决策 |
|---|---|---|---|
| 通用视频/视觉小说生成 | 视觉表现直接，创作者需求易理解 | 同类已有生成、编辑、导出、分支检查；视频质量高度依赖基础模型 | 缩到推理影游，加入证据与游戏状态约束 |
| 工业文档/供应链核验 | 约束可验证，业务价值明确 | 缺真实行业数据和业务方，不宜虚构落地收益 | 暂不转向 |
| 通用开发 Agent | 工程能力易展示 | 与成熟产品竞争，容易变成框架包装 | 不选 |
| 底层推理加速引擎 | 平台贡献突出 | 单人首次实现与稳定性风险大；偏离 Skills 完整应用 | 采用成熟引擎并测量应用层调度收益 |
| 推理影游制作 | 案件规则可检验，镜头有展示力，创作者能体验完整结果 | 故事趣味、角色一致性仍需人工评价 | 选定；限制案件规模并保留真实失败 |

这是一项有条件的竞争力判断，不是对冠军概率的统计估计或获奖保证。

## 必须做实的差异

1. 真相、角色知识和证据依赖分别建模；玩家动作不能改变作者设定的真相。
2. 固定检查器在正向证据条件的受限 DSL 中求解最小不动点，报告死锁和不可达结案，并返回可回放路径。证明不延伸到自然语言叙事质量。
3. Pi 调用受限工具创作和修复；修复前后保留版本和检查结果，不能改验收器。
4. 编辑影响分析决定哪些镜头过期；相同输入复用内容哈希缓存，失败不覆盖旧素材。
5. 可脱离模型服务运行的导出播放器；资源缺失或规则错误时阻止发布。

## 同类与来源

- [IntelliVNG](https://github.com/FE-square/IntelliVNG) 已有多 Agent、可视编辑、试玩、导出和结构/路径检查。上述单项均不声称首创。
- [YoLive 官方公告](https://www.globenewswire.com/news-release/2026/09/07/3357194/0/en/10-seconds-of-video-in-4-seconds-yoroll-launches-h3-superfast-and-yolive.html) 的 4 秒生成 10 秒视频使用 8 张 B200，不能推导单台 Spark 实时生成整部影片。
- [Sol-H3-Spark](https://nvlabs.github.io/Sana/Sol-Engine/Sol-H3-Spark/) 报告热态约 56 秒生成 5 秒 768p 音视频，常驻内存接近整机容量。其 [部署文档](https://github.com/NVlabs/Sana/blob/sol-engine/models/minimax_h3/Sol-H3-Spark/docs/setup.md) 明确尚未验证全新环境安装，部分权重需要访问许可；不能直接承诺已复现。Ref2VA 质量与额外内存需单测。
- [NVIDIA llama.cpp playbook](https://github.com/NVIDIA/dgx-spark-playbooks/blob/main/nvidia/llama-cpp/README.md) 提供 ARM64/SM121 部署路线。
- 评分和交付要求来自用户提供的三张规则图；参考作品分析在上级目录调研附录。赛事要求最终公开源码，当前仓库遵循用户指示保持私有。

## 实现与验收次序

案件播放器 → 固定规则检查与导出 → Pi 真实生成/修改/修复 → 本地媒体作业 → GPU 实测与陌生案件验证 → 浏览器完整试玩 → 私有 GitHub 提交。StepFun 无可用凭证时保留明确未配置状态，不伪造调用成绩。
