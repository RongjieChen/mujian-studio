## 作品名称与一句话介绍

**幕间 · 推理影游创作工坊**

让悬疑故事作者在本地完成案件编排、编辑、证据链检查、叙事初审和镜头制作，交付可独立游玩的 HTML 作品。

## 项目说明（超过 500 个中文字符）

幕间面向希望把短篇悬疑故事做成互动作品的创作者。用户输入故事背景、人物关系和希望表达的主题，Agent 将其编排为包含场景、人物、物证、证词、调查条件与不同结局的案件。创作者可以在工作台修改剧本、调整证据获取条件、查看修订记录，并直接试玩。作品完成后可以导出内嵌播放器与当前素材的 HTML 文件，玩家不需要安装开发环境，也不需要连接创作端模型。

我们把“生成了一段故事”与“交付了可运行作品”分开处理。Pi 负责执行专业 Skills，通过有限工具读取案件、提交草稿、局部修改、调用检查器和保存版本。案件检查器由固定代码实现，检查人物与证据引用、场景开放条件、关键证据可达性以及实际玩家规则下的结案路径。Agent 无法修改检查器；草稿修改后需要重新验证才能提交，不能仅凭模型声称检查通过就保存为验证版本。修复模式限制在依赖关系上，保护人物、对白、物证文字、真相和结案要求，避免通过删掉难点或改写真相获得表面的成功。

结构可通关仍不等于叙事合理。因此幕间另设只读叙事初审：模型检查时间线、可靠证据与人物陈述之间的疑点，引用具体原文字段，程序逐字核验引文来源。界面明确区分规则检查与模型初审；角色有意说谎不必然是漏洞，模型判断仍由作者确认。修改案件之后，旧初审会显示过期，不会继续冒充最新版本的结论。

DGX Spark 承担本地语言模型推理与素材生成。媒体管线使用 SDXL 生成场景图片，使用 Wan 2.2 TI2V 5B 生成短视频，可将当前图片作为首帧参考。单台机器通过顺序队列与模型内存切换协调语言模型和扩散模型，避免无控制地争用统一内存。素材记录提示输入指纹、种子、模型、耗时与来源；相关视觉设定改变后会提示素材过期，相同输入可复用已保存产物。缓存命中与本次真实模型生成分别记录。

工程实现采用 React、TypeScript、Express、Pi SDK 和 Python GPU 服务，提供手动编辑、乐观并发检查、历史版本恢复、任务取消与重试、素材导入和离线导出。测试围绕可验证结果组织：包括玩家动作重放、证据死锁、非法引用、修复越界、伪造检查、损坏图片、并发旧版本、取消恢复和脚本注入等情况。真实模型和媒体生成另留运行记录，不以模拟测试代替实机结果。

目前产品聚焦短篇、固定规则的推理作品。叙事初审不保证发现全部矛盾，结构检查不证明故事公平或有趣；自由对话、配音、跨镜头身份一致性和长片生成不属于当前已完成能力。我们希望用可编辑、可检查、可导出的创作流程，降低把一个想法交付成互动作品的工程门槛。

## 技术栈披露

| 层次 | 本项目用途 | 对外描述边界 |
|---|---|---|
| DGX Spark / GB10 / CUDA | 本地模型与扩散推理 | 性能仅引用本项目运行记录 |
| Pi SDK | Agent 会话、事件流、受限工具 | 不把 SDK 本身称为自主研发框架 |
| vLLM、机器既有的预量化 Qwen 模型 | 当前本地文本创作与初审 | 目录标称 Qwen3.8-27B-NVFP4，来源尚未独立核实；记录运行参数，不把现成权重称为自研量化 |
| PyTorch、Diffusers、SDXL、Wan 2.2 | 本地图片与短镜头 | 视频是创作阶段预生成；无音轨，不是实时世界模型 |
| StepFun | 保留可配置服务端接入路径 | 当前未取得本轮真实调用证据，不写“已使用”或“全链路 StepFun” |
| 自有 Skills 与检查器 | 专业任务约束、版本和发布检查 | 不将 Skills 文件数量等同于模型优化效果 |

NVIDIA 官方 Skills 本轮作为选型参考，未把“安装了全部官方 Skills”列为作品能力。需要向评委列明的 NVIDIA 能力是实际运行的硬件、CUDA 栈与量化推理实现。若提交前新增 StepFun 实测，应同步修改此表和数据流说明。
