# 幕间：产品与技术设计

幕间面向短篇悬疑故事作者，提供案件编排、人工编辑、规则检查、叙事初审、本地素材生成与独立 HTML 导出。

## 产品设计

幕间面向希望把短篇悬疑故事做成互动作品的创作者。用户输入故事背景、人物关系和希望表达的主题，Agent 将其编排为包含场景、人物、物证、证词、调查条件与不同结局的案件。创作者可以在工作台修改剧本、调整证据获取条件、查看修订记录，并直接试玩。作品完成后可以导出内嵌播放器与当前素材的 HTML 文件，玩家不需要安装开发环境，也不需要连接创作端模型。

我们把“生成了一段故事”与“交付了可运行作品”分开处理。Pi 负责执行专业 Skills，通过有限工具读取案件、提交草稿、局部修改、调用检查器和保存版本。案件检查器由固定代码实现，检查人物与证据引用、场景开放条件、关键证据可达性以及实际玩家规则下的结案路径。Agent 无法修改检查器；草稿修改后需要重新验证才能提交，不能仅凭模型声称检查通过就保存为验证版本。修复模式限制在依赖关系上，保护人物、对白、物证文字、真相和结案要求，避免通过删掉难点或改写真相获得表面的成功。

结构可通关仍不等于叙事合理。因此幕间另设只读叙事初审：模型检查时间线、可靠证据与人物陈述之间的疑点，引用具体原文字段，程序逐字核验引文来源。界面明确区分规则检查与模型初审；角色有意说谎不必然是漏洞，模型判断仍由作者确认。修改案件之后，旧初审会显示过期，不会继续冒充最新版本的结论。

DGX Spark 承担本地语言模型推理与素材生成。媒体管线使用 SDXL 生成场景图片，使用 Wan 2.2 TI2V 5B 生成短视频，可将当前图片作为首帧参考。单台机器通过顺序队列与模型内存切换协调语言模型和扩散模型，避免无控制地争用统一内存。素材记录提示输入指纹、种子、模型、耗时与来源；相关视觉设定改变后会提示素材过期，相同输入可复用已保存产物。缓存命中与本次真实模型生成分别记录。

工程实现采用 React、TypeScript、Express、Pi SDK 和 Python GPU 服务，提供手动编辑、乐观并发检查、历史版本恢复、任务取消与重试、素材导入和离线导出。测试围绕可验证结果组织：包括玩家动作重放、证据死锁、非法引用、修复越界、伪造检查、损坏图片、并发旧版本、取消恢复和脚本注入等情况。真实模型和媒体生成另留运行记录，不以模拟测试代替实机结果。

目前产品聚焦短篇、固定规则的推理作品。叙事初审不保证发现全部矛盾，结构检查不证明故事公平或有趣；自由对话、配音、跨镜头身份一致性和长片生成不在本版本功能范围内。我们希望用可编辑、可检查、可导出的创作流程，降低把一个想法交付成互动作品的工程门槛。


## 技术栈

| 层次 | 组件 | 用途 |
|---|---|---|
| 工作台 | React、TypeScript | 案件编辑、素材管理、试玩 |
| 应用服务 | Node.js、Express | 项目修订、作业调度与导出 |
| Agent | Pi SDK、专业 Skills | 受限工具调用与创作流程 |
| 语言推理 | vLLM / llama.cpp | 本地文本生成、编辑、修复与初审 |
| 图像与视频 | PyTorch、Diffusers、SDXL、Wan 2.2 TI2V 5B | 场景图与参考图短镜头 |
| 本地计算 | NVIDIA DGX Spark、GB10、CUDA | 统一内存下的模型推理 |
| 可选接口 | StepFun | 服务端兼容模型接口；不包含真实调用测试 |

测试用文本权重目录标称 Qwen3.8-27B-NVFP4，配置架构为 Qwen3_5ForConditionalGeneration，来源未独立核实。部署脚本复现服务参数，权重不随项目分发。模型配置和运行样本见 [实测数据](RELEASE-AUDIT.md)。

## 数据与规则

案件数据包含场景、人物、证据、问话、真相与结局。条件只表达已经取得的证据，玩家动作单调增加证据集合。检查器先计算可达集合，再重放真实动作，验证关键证据和结案要求是否可满足。

手动编辑与模型创作使用相同数据契约。保存采用版本冲突检查；恢复旧版会创建新修订。规则修复仅能改变依赖关系，只读叙事初审没有写工具。HTML 导出重新检查当前案件，并内嵌可用素材。

## 媒体调度

语言模型和媒体模型共享单台 Spark 的计算资源。应用使用顺序队列，通过语言模型休眠、KV 缓存释放、扩散模型卸载与恢复协调内存。任务记录模型、种子、输入指纹、开始结束时间及缓存来源。

素材缓存随视觉输入变化失效。图像可以作为视频首帧；更换首帧后，依赖它的视频会提示过期。镜头用于氛围，关键证据文字和游戏判定由确定性程序提供。
