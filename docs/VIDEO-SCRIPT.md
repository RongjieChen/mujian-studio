# 幕间：录屏与口播脚本

建议 4 分 30 秒。实际视频时长以组委会要求为准。录制前先查看 RELEASE-AUDIT，只有取得实测证据的步骤才按成功流程录制；服务故障时使用明确标注的已有实测录像，不伪装实时。

## 开拍准备

1. 打开工作台与一个已经导出的 HTML，浏览器建议 1440×900 或 1920×1080，缩放 100%。关闭个人通知和无关标签。
2. 开场作品为《末班渡轮的蓝色信封》，项目 ID `d6dea0b2-7673-4747-9aac-ab78e2beb989`，作者终审第 4 版。船尾场景使用本轮正式视频；另外两场景用本地生成图片。此作品由 AI 初稿、明确反馈修订与作者终审共同完成。
3. 另建测试副本用于故障注入和叙事矛盾演示，不修改成品。
4. 检查模型、媒体服务和队列；加载模型、生成视频等长步骤可以单独录制后剪辑，画面标注“过程节选”和真实总耗时。
5. 准备 README、Skills、实测报告与版本差异页面。API Key、SSH 地址与系统启动命令中的私密内容不入镜。

## 关键现场操作

固定规则路径在“检查与修复→玩家通关路径”中，作者视角包含剧透。成品关键镜头：船尾搜集替换信和蜡封 → 轮机舱找回原信 → 登记间取得值班出入记录 → 回轮机舱追问老陈 → 提出结案，选择老陈并勾选出入记录、原信和口供。其它证据也可勾选。未拿到原信时，关键追问不可用。录制前按完整路径走一遍。

离线成品在提交包“作品/末班渡轮的蓝色信封.html”，完整案件 JSON 可以重新导入；它不包含素材二进制，恢复全部创作素材需保留工作台数据备份。开场与结案截图以及短镜头原始 MP4 均随包提供。

叙事演示使用 `contradiction-audit-project.json` 对应副本：原真相称林知夏 23:12 离开茶室取走胶片，注入证词却称 23:00—23:30 的完整准确录像证明她一直在茶室。只有模型实际识别并引用这个冲突后才能录“发现”镜头；没有发现时如实展示漏检，不能用手写报告代替。

死锁测试点击“注入证据死锁（演示）”后再点“让 Agent 修复”。若模型未完成，保留失败记录，并选择之前成功的实际修复录像，注明这是预录结果。

离线证明最好录浏览器开发工具切换 Offline 的动作，再返回作品页；不能仅关闭工作台标签就说断网。导出的案件数据包含真相，适合分享游玩，不提供防剧透加密或防作弊承诺。

## 剪辑与素材原则

模型加载、排队、视频采样可以加速，但不能拼接成“输入后瞬间完成”。原始日志留在仓库证据目录，画面显示实际端到端时间。本轮正式档已实测成功：1280×704、121 帧、24 FPS、5.04 秒；作业耗时约 28 分 20 秒（含切换与加载，不含排队）。画面必须标注真实耗时和“过程节选”。不把草稿放大导出当作正式档模型生成。

不说“零成本”“保证无矛盾”“世界首创”“实时生成整部电影”。未使用的 StepFun 服务、配音或其他 SDK 不放到“已使用技术”画面中。
